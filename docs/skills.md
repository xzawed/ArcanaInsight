# ArcanaInsight — 기술 스킬 정의서

프로젝트 구현에 필요한 기술 영역과 세부 스킬을 정의한다.

---

## 1. 프론트엔드

### 1.1 Next.js App Router

- App Router 기반 페이지 라우팅 및 레이아웃 구성
- Server Components / Client Components 분리 판단
- Dynamic Routes (`/tarot/result/[id]`)
- Middleware를 활용한 인증 가드

### 1.2 Tailwind CSS & 다크 테마

- Tailwind 유틸리티 기반 UI 구현
- 다크 모드 기본 테마 (신비로운 분위기)
- 반응형 디자인 (PC/모바일 동등 지원)
- 커스텀 컬러 팔레트 (보라/남색/골드 계열)

### 1.3 Framer Motion 애니메이션

- 카드 셔플/펼침/뒤집기 애니메이션
- `layout`, `spring`, `staggerChildren` 활용
- `AnimatePresence`로 카드 배치 트랜지션
- `rotateY` 3D 뒤집기 효과
- 페이지 전환 애니메이션

### 1.4 캐릭터 렌더링

- 2D 애니메이션 스타일 캐릭터 표시
- 표정 전환 시스템 (6종 표정 세트)
- CSS/Lottie 아이들 모션 (머리카락, 눈 깜빡임)
- 캐릭터 선택 트랜지션 애니메이션
- 스프라이트 시트 최적화

### 1.5 채팅 UI & 타이핑 효과

- 말풍선 기반 채팅 인터페이스
- 한 글자씩 타이핑 효과 (SSE 스트리밍 연동)
- 표정 변화와 대사 동기화
- 스크롤 자동 관리

### 1.6 카드 인터랙션

- 부채꼴/원형 카드 배열
- PC: 호버 효과 (위로 뜨기 + 글로우)
- 모바일: 스와이프 탐색 + 탭 선택
- 스프레드별 레이아웃 (1/3/5카드)
- 반응형 리스케일링

---

## 2. 백엔드

### 2.1 Next.js API Routes

- `/api/tarot/session` — 세션 생성/관리
- `/api/tarot/reading` — Grok API 호출 + 해석 생성
- `/api/tarot/result/[id]` — 결과 조회
- `/api/auth/*` — 인증 관련 엔드포인트
- Rate limiting 적용

### 2.2 AI Provider 추상화

- `AIProvider` 인터페이스 정의
- `GrokProvider` 구현체 (xAI API 연동)
- 프롬프트 빌더 (시스템/컨텍스트/요청 조합)
- SSE 스트리밍 응답 처리
- 토큰 사용량 추적
- 향후 다른 모델로 교체 가능한 구조

### 2.3 서비스 모듈 아키텍처

- `DivinationService` 인터페이스 설계
- 서비스 레지스트리 패턴 (동적 서비스 로딩)
- 타로 서비스 구현 (MVP)
- 서비스별 독립된 프롬프트 관리
- 서비스 추가 시 코어 코드 변경 없음

### 2.4 세션 관리

- 상담 세션 생명주기 (생성 → 진행 → 완료/포기)
- 카드 선택 상태 추적
- 대화 히스토리 관리 (최근 N턴)
- 비회원 세션 → 로그인 시 연결

## 3. 데이터

### 3.1 Supabase 데이터베이스

- PostgreSQL 스키마 설계 및 마이그레이션
- Row Level Security (RLS) 정책
- 인덱스 최적화 (sessions, readings 테이블)
- jsonb 필드 활용 (card_interpretation, character_config)

### 3.2 Supabase Auth

- 소셜 로그인 설정 (카카오/구글/네이버)
- Supabase Auth Helpers for Next.js 연동
- 인증 미들웨어 구현
- 세션/토큰 관리

### 3.3 타로 카드 데이터

- 메이저 아르카나 22장 정의 (이름, 의미, 정/역방향 해석)
- 마이너 아르카나 56장 정의 (4 수트 × 14장)
- 커스텀 덱 확장 구조
- 스프레드 정의 (1/3/5카드, 위치별 의미)

## 7. 코드 테스트 및 코드 검증 작업

### 7.1 기본 규칙

- 코드 테스트 다음 코드 품질 검증 작업 수행 (기본)
- 코드 테스트 및 코드 품질 검증 과정중 미통과시 수정 이후 코드 테스트 작업부터 재시작 

### 7.2 코드 테스트 작업

- 구현 단위 및 전체 기능 통합테스트를 10회 이상 실시
- N번 테스트 작업을 수행시 각각 케이스를 다르게 적용하여 수행
- 테스트 결과 보고서 작성후 상세 내용을 HISTORY관리 및 Commit 메세지 반영

### 7.3 코드 품질 검증 작업

- 전체 코드품질 검증을 10회 이상 실시
- N번 품질 검증 작업 수행시 Critical 이슈 및 잠재적 위험요소 수정
- 품질 통과 기준은 Critical 이슈 0건 및 잠재적 위험 요소 0건
